# JRXML Web Designer — Architecture Documentation

> A code navigation manual for AI and human developers. Helps you quickly understand the project structure, core data flows, key files, and architectural patterns.

## 1. Project Overview

**JRXML Web Designer** is a browser-based visual report designer for designing and editing JasperReports JRXML template files.

- **Tech stack**: Vue 3 + TypeScript + Vite + Naive UI + vue-i18n
- **Version**: 0.4.6 (as of 2026-06)
- **Core invariant**: **Round-Trip Integrity** — edit in the designer → export JRXML → re-import → must produce the same visual result. Any bug in parse/generate/bind breaks this invariant.

### Bidirectional Data Flow

```
┌─────────────┐     ┌─────────────────┐     ┌──────────────┐
│  Vue Canvas  │ ⇄   │  Structured JSON │ ⇄   │  JRXML (XML) │
│  (UI Layer)  │     │  (Data Model)    │     │  (File)      │
└─────────────┘     └─────────────────┘     └──────────────┘
       ↑                    ↑                      ↑
  DesignerCanvas.vue   PDFDesigner.vue       jrxmlGenerator.ts
  Element rendering/     Centralized state       parse.ts
  interaction            management
```

## 3. Type System

The project has **two parallel sets of type definitions**, which must be kept distinct:

### UI Layer Types (`src/types/index.ts`)

The primary types used by Vue components and state management:

| Type | Description |
|------|------|
| `DesignElement` | Union type: `StaticTextElement \| TextFieldElement \| ImageElement \| LineElement \| RectangleElement \| EllipseElement \| BreakElement \| FrameElement \| TableElement` |
| `Band` | A layout region (title, detail, pageHeader, etc.) containing an elements array |
| `BandType` | `'detail' \| 'pageHeader' \| 'pageFooter' \| 'title' \| 'summary' \| 'columnHeader' \| 'columnFooter' \| 'background' \| 'lastPageFooter' \| 'noData'` |
| `TableElement` | Table element, containing `columns` (flat) and `children` (hierarchical) |
| `TableColumn` | Table column, containing uuid, width, name, and per-region Cells |
| `ColumnGroup` | Column group, a recursive structure containing children: `(ColumnGroup \| TableColumn)[]` |
| `TableCell` | `{ enable: boolean; element?: DesignElement; rowSpan?: number }` |
| `ReportProperties` | Report properties (page size, margins, default font, etc.) |
| `Box` | Border style (supports independent settings per side) |

### Internal Table Types (`src/types/table.ts`)

Used by table utilities such as `ColumnFactory` and `ColumnTreeSync`:

| Type | Description |
|------|------|
| `Column` | extends `BaseColumn`, includes `detailCell` |
| `ColumnGroup` | extends `BaseColumn`, includes `children: (Column \| ColumnGroup)[]` |
| `BaseColumn` | uuid, name, width, tableHeader, columnHeader, columnFooter, tableFooter, etc. |
| `Cell` | extends `BaseCell`, includes `rowSpan`, `enable` |
| `BaseCell` | height, width, style, backcolor, forecolor, box, element, etc. |
| `TableElement` | Table element interface (type: 'table') |

### Cell Format

**Key convention**: Cell content is uniformly wrapped in `.element`:

```typescript
{
  enable: true,
  rowSpan: 2,       // optional, number of rows spanned
  element: {        // cell content
    type: 'staticText' | 'textField',
    text: 'Title text',           // used by staticText
    expression: '$F{fieldName}', // used by textField
    x: 0, y: 0, width: 100, height: 30,
    textAlignment: 'Center',
    verticalAlignment: 'Middle',
  }
}
```

## 4. Core Data Flows

### 4.1 JSON → JRXML (Generation)

```
Entry: src/utils/jrxmlGenerator.ts → generateJRXMLContent()
     ↓
Build XML header: src/utils/jrxml/xmlBuilder.ts → buildJasperReportOpenTag()
     ↓
Flatten the JSON model into JasperReports XML
  - Traverse bands → elements → properties
  - Tables: columns/children → jr:column/jr:columnGroup
  - rowSpan calculation (see section 8)
     ↓
Output: JRXML string
```

**Key functions**:
- `generateJRXMLContent(reportData, options)` — main entry point
- `buildJasperReportOpenTag(props)` — builds the `<jasperReport>` opening tag
- `calculateMaxGroupDepth(node, depth)` — calculates the maximum nesting depth of column groups
- `countGroups(node)` — counts the total number of group nodes
- `getMaxGroupDepthInChildren(children, baseDepth)` — gets the max group depth among child nodes

### 4.2 JRXML → JSON (Parsing)

```
Entry: src/utils/jrxml/parse.ts → parseJRXMLContent()
     ↓
Parse XML using the browser's DOMParser
     ↓
Namespace handling (3-tier fallback strategy):
  1. tagName (direct access)
  2. getElementsByTagNameNS (namespace-aware)
  3. localName (local-name matching)
     ↓
Extract:
  - properties → ReportProperties
  - bands → Band[] (recursively containing elements)
  - fields → Field[]
  - parameters → ReportParameter[]
  - datasets → TableDataset[]
  - variables → ReportVariable[]
  - styles → ReportStyle[]
     ↓
Table parsing:
  jr:column → TableColumn
  jr:columnGroup → ColumnGroup (recursive children)
     ↓
Output: JSON structure
```

**Namespace**: `http://jasperreports.sourceforge.net/jasperreports`

**Key functions**:
- `parseJRXMLContent(xmlString)` — main entry point
- `parseReportProperties(root)` — parses report properties
- `parseBands(root)` — parses all Bands
- `parseTableElement(tableElement)` — parses a table (including recursive column groups)

### 4.3 JSON → UI (Binding)

```
Entry: src/components/PDFDesigner.vue
     ↓
Vue 3 reactive refs hold the JSON model:
  reportProperties, bands, fields, parameters, etc.
     ↓
DesignerCanvas.vue renders elements
  - Selects the rendering component based on element.type
  - Drag/resize/select operations directly mutate the JSON model
     ↓
The properties panel (ElementProperties.vue) displays properties of the selected element
  - Editing a property → mutates the JSON → canvas updates in real time
```

**Key responsibilities**:
- Manages reactive state for all report data

## 6. Table Column Grouping System

This is the most complex subsystem in the project, involving multi-layer data synchronization.

### 6.1 Dual Data Model

Tables have two representations that must be kept in sync:

```
element.children (hierarchical structure, source of truth)   element.columns (flat leaf array, compat view)
┌──────────────────────┐                   ┌──────────────────────────┐
│ ColumnGroup A        │                   │ Column 1 (root)          │
│   ├── Column 1       │  syncTableColumns │ Column 2 (root)          │
│   └── Column 2       │ ─────────────────→│ Column A (in group)      │
│ Column 3 (root)      │                   │ Column B (in group)      │
└──────────────────────┘                   └──────────────────────────┘
```

**Rules**:
- `children` is the **source of truth**
- `columns` is a **read-only compatibility view** rebuilt from `children`
- After every mutation, `syncTableColumns()` must be called to rebuild `columns`

### 6.2 Sync Utilities (`src/utils/table/ColumnTreeSync.ts`)

```typescript
// Core sync function
syncTableColumns(tableElement: TableElement): void
  - Recursively updates the width of all column groups
  - Rebuilds columns from children (via TableUtils.getLeafColumns)
  - Calculates the maximum nesting level and updates rowSpan for ungrouped root-level columns
  - Updates the total table width

// Creation utilities
createDefaultColumn(name, width?) → Column       // creates a leaf column
createDefaultColumnGroup(name) → ColumnGroup      // creates an empty group

// Operation utilities
findInParentArray(children, targetUuid)           // recursively finds the array containing the target UUID
ungroupColumnGroup(children, groupUuid)           // dissolves a group (promotes children to parent level)
```

### 6.3 Column Factory (`src/utils/table/ColumnFactory.ts`)

```typescript
// Factory class
ColumnFactoryImpl
  - createColumn(config) → Column
  - createColumnGroup(config) → ColumnGroup
  - createColumns(columns[]) → (Column | ColumnGroup)[]

// Static utility class
TableUtils
  - getLeafColumns(children) → Column[]           // extracts all leaf columns
  - calculateGroupWidth(group) → number            // calculates a group's total width
  - updateAllColumnGroupWidths(children)           // recursively updates the width of all groups
  - findAllColumns(children) → Column[]            // finds all columns
  - moveColumn(children, uuid, direction)          // moves a column
  - addColumnAfter(children, afterUuid, column)    // adds a column after a given one
  - removeColumn(children, uuid)                   // removes a column
```

### 6.4 rowSpan Calculation Formula

rowSpan determines how many header rows a cell spans, and is key to table rendering:

| Scenario | rowSpan formula | Description |
|------|-------------|------|
| Ungrouped root-level leaf column | `maxGroupDepth + 1` | Fills all header rows |
| Nested standalone leaf column | `maxDepth - depth + 1` | Extends down to the deepest group header |
| Group node header | `1` | Occupies only its own row |

Where `maxGroupDepth` = the path length from the root to the deepest group node (counting only groups, not leaves).

**Example**:
```
Root
├── ColumnGroup A (depth=0, maxDepth=1)
│   ├── Column 1 (rowSpan = 1-0+1 = 2)
│   └── ColumnGroup B (depth=1, maxDepth=1)
│       └── Column 2 (rowSpan = 1-1+1 = 1)
└── Column 3 (root standalone, rowSpan = 1+1 = 2)
```

### 6.5 Column Tree UI (`ColumnTreeNode.vue`)

A recursive component that renders the column hierarchy:

```
Group node:  [▶] [▦] [name input] [width (auto)] [↑↓⊕+⧉⊟×]
Leaf node:   [  ] [☰] [name input] [width input] [↑↓+⧉×]
```

- Group node: expand/collapse, blue left border, child-node indentation
- Leaf node: editable width
- Action buttons: move up, move down, add column inside group (⊕), add column after (+), add group after (⧉), ungroup (⊟), delete (×)

## 12. Key Architectural Patterns

### 12.1 Centralized State Management (No External Library)

All state lives as Vue 3 reactive refs centralized in `PDFDesigner.vue`, passed between components via props/emit. The advantage is simplicity and directness; the drawback is more prop drilling when the component hierarchy gets deep.

### 12.2 Dual Data Source Sync (Tables)

A table's `children` (hierarchical) and `columns` (flat) must be kept in sync. After every mutation, `syncTableColumns()` must be called. This is the easiest place to introduce bugs.

### 12.3 Namespace Fallback Strategy (JRXML Parsing)

JasperReports XML uses namespace prefixes (e.g. `jr:column`), but different tools generate XML with different namespace handling. The parser uses a 3-tier fallback strategy to ensure compatibility.

### 12.4 Cell `.element` Wrapping

All cell content uniformly uses the `{ enable, element: { type, text/expression, ... }, rowSpan }` format. The parse, generate, and canvas layers must all stay consistent with each other.

### 12.5 UUID Requirement

The JasperReports XSD requires every element to have a UUID. All newly created elements/columns/groups are generated via `crypto.randomUUID()`.

## 13. Common Development Task Guides

### Adding a New Design Element Type

1. Define the new element interface in `src/types/index.ts`
2. Add it to the `DesignElement` union type
3. Add parsing logic in `parse.ts`
4. Add generation logic in `jrxmlGenerator.ts`
5. Add a rendering branch in `DesignerCanvas.vue`
6. Add the properties panel in `ElementProperties.vue`
7. Add tests

### Modifying the Table Column Structure

1. Modify the sync logic in `ColumnTreeSync.ts`
2. If parsing needs changes, update the table-parsing section in `parse.ts`
3. If generation needs changes, update the table-generation section in `jrxmlGenerator.ts`
4. Run `npm run test` to confirm round-trip integrity

### Debugging JRXML Issues

1. Export the problematic JRXML file
2. Check the fixture in `parse.test.ts`
3. Open the JRXML in Jaspersoft Studio to validate the XML format
4. Check `round-trip-integrity.test.ts` to confirm round-trip integrity
